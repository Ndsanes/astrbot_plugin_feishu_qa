# 更新日志

## v0.8.7 (2026-09-16)

### 变更

- **`/learn` 支持"把聊天记录转发进群"作为素材**(实测确认的推荐用法):
  官方 QQ 机器人在**服务端**就把合并转发展开成纯文本(message_type=102,
  `[群聊的聊天记录]` + `=== 消息 N ===` + `[发送者]`)随 `content` 下发,
  因此插件拿到的就是完整转录,**不需要**任何转发组件解析,也**不需要**打开
  `group_message_history_enable` 或新增落库。这种素材由转发者人工筛选、
  自带发送者与嵌套引用,信噪比远高于"抓最近 N 条群聊"(群里绝大多数是闲聊),
  这也是群成员无需加机器人好友就能提供素材的路径。
- `/learn` 素材取用改为三档优先级:**聊天记录转录 > 引用消息 > 平台历史**
  (后者仅 aiocqhttp)。此前只走 `get_group_msg_history`,在 QQ 上直接回
  "当前平台不支持";现在群内引用学习内容或转发记录发 `/learn` 即可。
  三条路都取不到时给出可操作提示,而不是死胡同。候选回复会标注素材来源。

### 修复

- **超长素材被静默丢弃**:`build_learn_prompt` 原来"装不下就 break",遇到
  单条超过 4000 字的素材(如整段转发转录)会整条丢掉,prompt 素材区为空、
  模型无从判断——表现为 `/learn` 无提示地判"没有新问答"。改为首尾保留式
  截断(问句在转录开头、结论在结尾,砍任一端都会毁掉这条问答)并显式标注
  省略,模型不会把截断误当对话结束。

## v0.8.6 (2026-09-15)

### 修复

- **自动附链发出无关章节**:用户问"Cakewalk 的混音台怎么打开",插件附上的
  三条直达链接是"连接MIDI设备""Clip重叠""搜索不到自带音源"——与提问毫无
  关系。根因是附链只顾**检索顺序**:KB 检索的相关度是为**该次检索词**服务的,
  靠前的 FAQ 只说明它与"Cakewalk"同域,不代表答得上用户的问题(实测这三个
  条目按用户原问题判定只有 0.49~1.12 分,全在 LOW 区)。
- 现改为用**用户原问题**(剥掉 @唤醒)做一次本地确定性判定,沿用与 Tier 0
  直答同一套证据标准:①本地判定 MEDIUM 以上;②条目头部(症状标签/标题/分类)
  覆盖到查询主题词。不达标就不附链——附链是对用户的承诺("你的答案在这里"),
  宁可少一条,也不把无关章节塞给用户。输出同时改为**按相关度降序**,不再随
  检索顺序浮动。仍为零 LLM、零网络的纯本地计算。
- 校准:20 条真实 query 的正确条目**无一被误拦**(0/20);全语料 124 组
  "用户会怎么问"措辞自测,自身条目附着率 100%;事故现场三个条目全部拦下。
  查询本身不含主题词时(如只问"cakewalk")闸门不生效,避免正常提问被一律拒绝。

## v0.8.5 (2026-09-15)

### 修复

- **Tier 0 误命中**:群内"cakewalk sonar的混音台在哪"曾以 6.59 分直答
  【如何登录激活】(生产阈值即 6.5)。根因是全篇文档都处于 Cakewalk 语境,
  "cakewalk/sonar"这两个满语料高频词足以把任意条目顶过阈值,而真正携带
  意图的"混音台"在全语料零命中——被硬答一条不相干的,还把主 Agent 挡在
  门外。现引入**主题词支撑闸门**:按 IDF 识别查询中的"主题词"(排除满语料
  领域词),条目若在症状标签/标题/分类三处都覆盖不到任一主题词,分数乘以
  0.3 压回低分区,交还主 Agent 处理。校准:20 条真实 query 判定完全不变
  (直答 17/20),4 条负例零泄漏,误命中 6.59→1.98;门槛取自 r8268/r8394
  两份语料的稳定平台期。
